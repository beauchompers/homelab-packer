# RHEL 9.8 Proxmox Template Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `rhel-9.8/` Packer build that produces the `packer-rhel-98` (BIOS) and `packer-rhel-98-uefi` (UEFI + Secure Boot) Proxmox templates for Terraform to clone.

**Architecture:** One `proxmox-iso` source with the same `uefi` toggle as `ubuntu-24.04/ubuntu.pkr.hcl`. Packer renders `ks.pkrtpl.hcl` with `templatefile()` into `cd_content` as `ks.cfg` on an `OEMDRV`-labelled CD, which the installer reads automatically. Shell provisioners check the result, unregister from Red Hat and clean state before conversion.

**Tech Stack:** Packer 1.15, proxmox plugin 1.2.2, xorriso (installed), Anaconda kickstart, Proxmox VE 9.2 on `readylabone`.

**Spec:** `docs/superpowers/specs/2026-11-16-rhel-9.8-template-design.md`

## Global Constraints

- ISO `local:iso/rhel-9.8-x86_64-boot.iso`, sha256 `18fecefe070e9c40502287281ec86e3bd4d64e2f48796a1cb166d9371308e5e6`.
- Template names `packer-rhel-98` / `packer-rhel-98-uefi`; VM IDs 500 / 501; node `readylabone`, storage `local-lvm`, bridge `vmbr0`.
- GPT `/dev/sda`: 1 = `biosboot` (BIOS) or `/boot/efi` (UEFI), 2 = `/boot`, 3 = LVM PV and last; VG/LV `rhel-vg/rhel-lv` on `/`.
- `rhsm_org`, `rhsm_activation_key`, `ssh_password` are `sensitive = true`; real values only in gitignored `rhel-9.8/readylabone.pkrvars.hcl` (`*.pkrvars.hcl` is already in `.gitignore`).
- Same VM shape as the Ubuntu builds: 8192 MB, 2 cores, 20G raw scsi disk, virtio-scsi-pci, virtio NIC, `os = "l26"`, `qemu_agent = true`, `cloud_init = true`, `unmount_iso = true`.
- UEFI: `bios = "ovmf"`, `machine = "q35"`, `efi_config { efi_storage_pool = "local-lvm", efi_type = "4m", pre_enrolled_keys = true }`.

## Review Focus

- The ISO's GRUB menu defaults to "Test this media & install": the boot command must select "Install Red Hat Enterprise Linux 9.8" — checked by watching the console (screendump) in Task 2.
- A kickstart error or failed registration leaves Anaconda waiting for input and packer waiting for SSH: `ssh_timeout = "1h"` (not 24h) so a broken build fails within the hour — Task 1.
- Anaconda copies the kickstart, with the activation key, to `/root/anaconda-ks.cfg` and `/root/original-ks.cfg`: cleanup deletes them and the check step fails if `grep -r <org> /root /var/log/anaconda` finds the org ID — Task 1, verified in Task 2.
- Anaconda may order partitions differently from the kickstart: the check step asserts `sda1 sda2 sda3` and the PV on sda3 — Task 1.
- cloud-init must not configure the VM during the build, yet must run on clones: the clone test in Task 4 asserts `cloud-init status` is `done` and the ciuser exists.

### Task 1: The `rhel-9.8/` build files

**Files:**
- Create: `rhel-9.8/rhel.pkr.hcl`, `rhel-9.8/vars.pkr.hcl`, `rhel-9.8/ks.pkrtpl.hcl`, `rhel-9.8/files/99_pve.cfg.txt` (copy of `ubuntu-24.04/files/99_pve.cfg.txt`), `rhel-9.8/README.md`
- Create (local, gitignored): `rhel-9.8/readylabone.pkrvars.hcl` — Proxmox values from `ubuntu-24.04/readylabone.pkrvars.hcl`, plus the ISO above, `proxmox_vm_id = 500`, `proxmox_template_name = "packer-rhel-98"`, `rhsm_org` and `rhsm_activation_key` (the values the user gave)

**Interfaces:**
- Produces: variables as in `ubuntu-24.04/vars.pkr.hcl` plus `uefi` (bool, false), `rhsm_org`, `rhsm_activation_key` (sensitive strings); locals `template_name`, `template_description`; source `proxmox-iso.rhel`.
- `ks.pkrtpl.hcl` takes: `uefi`, `rhsm_org`, `rhsm_activation_key`, `ssh_username`, `ssh_password`.
