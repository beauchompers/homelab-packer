# RHEL 9.8 Proxmox template: design

## Why
Another base template for Terraform to clone, the same way as the Ubuntu 22.04 / 24.04 templates:
full clone, cloud-init (`ciuser`/`cipassword`/`ipconfig0`), guest agent for the IP, then the
resize script.

## Goals
- New `rhel-9.8/` build in this repo that produces `packer-rhel-98` (BIOS) and, with `uefi=true`,
  `packer-rhel-98-uefi` (OVMF + q35 + pre-enrolled Secure Boot keys), like the Ubuntu builds.
- Disk on `/dev/sda`, GPT: partition 1 = BIOS boot (BIOS) or ESP `/boot/efi` (UEFI), 2 = `/boot`,
  3 = LVM PV, last. VG/LV `rhel-vg/rhel-lv` on `/` (device `/dev/mapper/rhel--vg-rhel--lv`).
- `qemu-guest-agent` and `cloud-init` enabled, Proxmox cloud-init drive, ISO unmounted.
- Fully patched at build time; unregistered from Red Hat before it becomes a template.

## Non-goals
- The Terraform change (see below), RHEL 8.9, Satellite / local mirrors.

## Anti-goals
- Org ID, activation key or passwords in git, or printed in build logs.
- Clones sharing one Red Hat system identity, machine-id or SSH host keys.

## Constraints
- ISO: `local:iso/rhel-9.8-x86_64-boot.iso` (boot ISO, no packages),
  sha256 `18fecefe070e9c40502287281ec86e3bd4d64e2f48796a1cb166d9371308e5e6`.
  Packages come from Red Hat's CDN, so the install registers with an activation key.
- Proxmox node `readylabone`, storage `local-lvm`, bridge `vmbr0`, VM IDs 500 (BIOS) / 501 (UEFI).
- Terraform's resize script needs `sgdisk`, `parted`, `pvresize`, `lvresize` in the image.

## Approaches
1. **Own `rhel-9.8/` directory copying the Ubuntu builds' structure (picked).** Matches how the repo
   handles each Ubuntu version.
2. Kickstart over http (`inst.ks=http://...`): rejected, the live installer couldn't reach packer's
   http server early in boot on q35 when we tried that with Ubuntu.
3. One generic multi-distro source shared with Ubuntu: rejected, reworks two working builds to save
   about 60 duplicated lines.

Package source: activation key + CDN (picked) over uploading the ~10 GB DVD ISO (stale until updated).
Volume names: `rhel-vg/rhel-lv` plus a one-line Terraform change (picked) over reusing `ubuntu-vg`.

## Design
- **Files:** `rhel-9.8/rhel.pkr.hcl`, `vars.pkr.hcl`, `ks.pkrtpl.hcl`, `files/99_pve.cfg.txt`,
  `README.md`; local gitignored `readylabone.pkrvars.hcl` (Proxmox values copied from the Ubuntu
  builds, plus `rhsm_org` / `rhsm_activation_key`).
- **Kickstart delivery:** packer renders `ks.pkrtpl.hcl` with `templatefile()` into `cd_content` as
  `ks.cfg` on a CD labelled `OEMDRV`, which the installer reads automatically. Same for BIOS and UEFI.
  The boot command only picks "Install Red Hat Enterprise Linux 9.8" in the ISO's GRUB menu.
  `boot_wait` long enough for GRUB under OVMF (25s worked for Ubuntu).
- **Secrets:** `rhsm_org`, `rhsm_activation_key`, `ssh_password` are `sensitive = true` variables.
- **Kickstart:** text install; `rhsm --organization --activation-key`; DHCP on the first NIC;
  root locked; build user from `ssh_username` / `ssh_password` with passwordless sudo (as the Ubuntu
  templates do); SELinux enforcing; firewall on with ssh; timezone US/Mountain; explicit partitions
  (`biosboot` or `/boot/efi`, then `/boot`, then the PV with `--grow`), `rhel-vg/rhel-lv` filling the
  VG; packages: minimal environment, `qemu-guest-agent`, `cloud-init`, `cloud-utils-growpart`,
  `gdisk`, `parted`, and for UEFI `shim-x64`, `grub2-efi-x64`, `mokutil`; no swap.
- **Provisioners:** install `99_pve.cfg`; check step that fails the build unless partitions are
  1 / 2 / 3 with `/boot` on sda2 and `rhel-vg/rhel-lv` on sda3, `sgdisk` is present, the guest agent
  is enabled, and (UEFI) Secure Boot is enabled with `shim-x64` installed; then
  `subscription-manager unregister` + `clean`, `dnf clean all`, remove SSH host keys, truncate
  machine-id, `cloud-init clean --logs`.
- **Verify:** `packer validate` for both; build 500 and 501; full-clone each, set cloud-init user and
  DHCP, and check EFI / Secure Boot (UEFI), partitions, agent IP, cloud-init done, the resize script
  with the RHEL LV path after growing the disk, and that the clone is not registered; destroy clones.

## Terraform (other repo, for reference)
Make the LV path in the resize script a per-template value:
`/dev/mapper/ubuntu--vg-ubuntu--lv` for Ubuntu, `/dev/mapper/rhel--vg-rhel--lv` for RHEL.

## Left to the builder
Exact kickstart syntax, how cloud-init is kept from running during the build, and the GRUB menu
keystrokes, verified against the real ISO.
